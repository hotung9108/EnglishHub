# File Upload API Guide — Module Listening Audio & Submission Files

> Scope: backend only. This document describes the **presigned direct-upload** flow used by
> two features:
>
> 1. Teacher uploading **listening audio** for a `LISTENING` module.
> 2. Student uploading **speaking recordings** and **essay documents** for a submission.
>
> Both features never send the file bytes to the backend. The backend only issues a short-lived
> **presigned PUT URL**; the client uploads the file directly to S3-compatible object storage.

## 0. Shared concept: presigned direct upload

```text
Client (browser)                         Backend (Spring Boot)                Object storage (S3/R2/MinIO)
      |                                          |                                       |
      |  1. POST .../upload-url  { mimeType }    |                                       |
      |----------------------------------------->|                                       |
      |   { uploadUrl, storageKey, expiresAt }   |                                       |
      |<-----------------------------------------|                                       |
      |                                          |                                       |
      |  2. PUT uploadUrl  (raw bytes, Content-Type = mimeType)                          |
      |--------------------------------------------------------------------------------->|
      |   200 / 204 OK                                                                   |
      |<---------------------------------------------------------------------------------|
      |                                          |                                       |
      |  3. POST .../confirm  { storageKey }     |  probe objectExists(storageKey)       |
      |----------------------------------------->|-------------------------------------->|
      |   { ...UploadStatus: READY | FAILED }    |                                       |
      |<-----------------------------------------|                                       |
```

Key properties:

- The presigned PUT URL **expires** (currently **15 minutes**). Request a new one if it expires.
- The `Content-Type` header of the direct PUT **must equal** the `mimeType` sent in step 1,
  because it was signed into the URL. A mismatch makes object storage reject the PUT with `403`.
- `storageKey` is generated by the backend and is what you persist/return in later calls. Never
  build a storage key by hand.
- When `app.storage.s3.enabled=false`, storage calls fail with `500` and the message
  `"Lưu trữ chưa được cấu hình."`.

## 1. Module listening audio (teacher)

Replaces the previous `multipart/form-data` endpoint. The upload is now a 3-step flow, and the
backend exposes a `GET` endpoint so students can play the audio.

**Permissions:** teacher who owns the assignment only. `ADMIN` and other teachers get `403`.

### 1.1 Request an upload URL

```http
POST /api/v1/modules/{moduleId}/audio
Authorization: Bearer <teacher access token>
Content-Type: application/json

{ "mimeType": "audio/mpeg" }
```

Allowed `mimeType` values and the storage-key extension they produce:

| `mimeType`                       | Extension |
| :------------------------------- | :-------- |
| `audio/mpeg`, `audio/mp3`        | `.mp3`    |
| `audio/wav`, `audio/x-wav`, `audio/wave` | `.wav` |
| `audio/mp4`, `audio/m4a`, `audio/x-m4a` | `.m4a` |

Response `200 OK`:

```json
{
  "message": "Lấy link upload audio thành công.",
  "uploadUrl": "https://storage.example.com/bucket/modules/42/audio/<uuid>.mp3?X-Amz-Signature=...",
  "storageKey": "modules/42/audio/<uuid>.mp3",
  "expiresAt": "2026-10-17T12:30:00Z",
  "sourceAudioUploadStatus": "UPLOADING"
}
```

Re-requesting an upload URL **replaces** any previous pending audio: the old object is deleted
(best effort, after the request commits) and the module metadata points to the new key with
status `UPLOADING`.

### 1.2 PUT the file to object storage

```http
PUT <uploadUrl from step 1>
Content-Type: audio/mpeg

<raw file bytes>
```

No `Authorization` header is used here — the signature in the URL authorises the write.
A successful upload returns `200` or `204`. If you get `403`, the URL expired or the
`Content-Type` does not match the `mimeType` from step 1.

### 1.3 Confirm the upload

```http
POST /api/v1/modules/{moduleId}/audio/confirm
Authorization: Bearer <teacher access token>
Content-Type: application/json

{ "storageKey": "modules/42/audio/<uuid>.mp3" }
```

The backend probes object storage for the object and sets the module status:

Success (`200 OK`):

```json
{
  "message": "Xác nhận upload audio thành công.",
  "sourceAudioStorageKey": "modules/42/audio/<uuid>.mp3",
  "sourceAudioUploadStatus": "READY"
}
```

Not uploaded (`200 OK`, status is set to `FAILED`):

```json
{
  "message": "File audio chưa được tải lên kho lưu trữ.",
  "sourceAudioStorageKey": "modules/42/audio/<uuid>.mp3",
  "sourceAudioUploadStatus": "FAILED"
}
```

> The `FAILED` case returns HTTP `200` on purpose: the status change is part of the same
> transaction, so returning it in the body lets it be committed. Clients must branch on
> `sourceAudioUploadStatus`, not on the HTTP status code.

If the `storageKey` does not belong to this module the call fails with `400` and
`{"error":"storageKey không khớp với module."}`.

### 1.4 Stream / play the audio

```http
GET /api/v1/modules/{moduleId}/audio
Authorization: Bearer <teacher or student access token>
```

- Returns the **raw audio bytes** with `Content-Type` set to the stored mime type and
  `Cache-Control: private, max-age=3600`.
- Access mirrors `GET /api/v1/modules/{moduleId}`: the owning teacher and students that are
  members of the assignment's class are allowed; everyone else (`ADMIN`, other teachers,
  non-member students) gets `403`.
- `404` with `{"error":"Module chưa có file audio."}` when the module has no audio key, or when
  the key exists but the object is missing in storage.

Because the endpoint requires the `Authorization` header, a native `<audio src="...">` tag cannot
play it directly. The frontend must fetch the bytes and turn them into an object URL:

```ts
const response = await api.get(`/modules/${moduleId}/audio`, { responseType: 'blob' });
const objectUrl = URL.createObjectURL(response.data);
// <audio src={objectUrl} /> — call URL.revokeObjectURL(objectUrl) on unmount
```

### 1.5 Error reference

| HTTP | Message                                        | Cause                                              |
| :--- | :--------------------------------------------- | :------------------------------------------------- |
| 400  | `Module này không hỗ trợ upload audio.`        | Module skill is not `LISTENING` (request/confirm). |
| 400  | `Định dạng file audio không được hỗ trợ.`      | `mimeType` missing or not in the allowlist.        |
| 400  | `storageKey không khớp với module.`            | Confirm called with a key from another upload.     |
| 403  | `Bạn không có quyền thực hiện thao tác này.`   | Caller is not the owning teacher / not a member.   |
| 404  | `Module chưa có file audio.`                   | `GET` before upload, or object missing.            |
| 500  | `Lưu trữ chưa được cấu hình.`                  | `app.storage.s3.enabled=false`.                    |

## 2. Submission file uploads (student)

The submission flow predates this guide and already used presigned uploads. It is documented
here so both flows live in one place. Two variants exist, on the **submission module** (not the
assignment module).

**Permissions:** the student who owns the submission, and only while the submission is
`IN_PROGRESS`.

### 2.1 Speaking recording (`audio`)

Allowed when the referenced assignment module is a `RECORDING` task **or** has skill `SPEAKING`.

```http
POST /api/v1/submission-modules/{submissionModuleId}/audio-upload-url
Authorization: Bearer <student access token>
Content-Type: application/json

{ "mimeType": "audio/webm" }
```

Allowed `mimeType`: `audio/webm` (→ `.webm`), `audio/mpeg` (→ `.mp3`), `audio/wav` (→ `.wav`).

Response `200 OK`:

```json
{
  "uploadUrl": "https://storage.example.com/...&X-Amz-Signature=...",
  "storageKey": "submissions/<submissionId>/module-<submissionModuleId>/audio.webm",
  "expiresAt": "2026-10-17T12:30:00Z"
}
```

Then PUT the bytes to `uploadUrl` with the matching `Content-Type`. There is **no confirm
endpoint** for submissions: the status is resolved when the module is submitted (see 2.3).

### 2.2 Essay document (`document`)

Allowed only when the assignment module is an `ESSAY` (the `REWRITE` task type is intentionally
rejected — rewrite answers questions like a quiz).

```http
POST /api/v1/submission-modules/{submissionModuleId}/document-upload-url
Authorization: Bearer <student access token>
Content-Type: application/json

{ "mimeType": "application/pdf" }
```

Allowed `mimeType`:
`application/pdf` (→ `.pdf`),
`application/vnd.openxmlformats-officedocument.wordprocessingml.document` (→ `.docx`).

Response shape is identical to 2.1, with `storageKey`
`submissions/<submissionId>/module-<submissionModuleId>/essay.<ext>`.

Errors for both use `400` with `"Không thể upload ghi âm cho phần làm bài này."` /
`"Không thể upload tài liệu cho phần làm bài này."` (wrong module type or submission not
`IN_PROGRESS`) and `"Định dạng file không được hỗ trợ."` (bad mime type).

### 2.3 Submitting the module

```http
POST /api/v1/submissions/{submissionId}/submit
```

For file-based modules the backend probes object storage for the expected keys:

- Audio candidates, in order: `audio.webm`, `audio.mp3`, `audio.wav`.
- Document candidates, in order: `essay.pdf`, `essay.docx`.

The first key that exists is stored with `audioUploadStatus`/`docUploadStatus` = `READY`; if none
exists the status stays `UPLOADING`. **The module is submitted either way** — a missing file does
not fail the submit call; it is simply recorded as not uploaded.

## 3. Complete examples

### 3.1 Teacher uploads listening audio (curl)

```bash
TOKEN="<teacher access token>"
MODULE_ID=42

# 1. Request the presigned URL
RESPONSE=$(curl -s -X POST "http://localhost:8080/api/v1/modules/$MODULE_ID/audio" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"mimeType":"audio/mpeg"}')

UPLOAD_URL=$(echo "$RESPONSE" | jq -r '.uploadUrl')
STORAGE_KEY=$(echo "$RESPONSE" | jq -r '.storageKey')

# 2. Upload the bytes directly to object storage
curl -s -X PUT "$UPLOAD_URL" \
  -H "Content-Type: audio/mpeg" \
  --data-binary @lesson.mp3

# 3. Confirm
curl -s -X POST "http://localhost:8080/api/v1/modules/$MODULE_ID/audio/confirm" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"storageKey\":\"$STORAGE_KEY\"}"

# 4. Stream it back
curl -s "http://localhost:8080/api/v1/modules/$MODULE_ID/audio" \
  -H "Authorization: Bearer $TOKEN" --output downloaded.mp3
```

### 3.2 Teacher uploads listening audio (browser / axios)

```ts
async function uploadModuleAudio(moduleId: number, file: File) {
  // 1. Ask the backend for a presigned URL
  const { data } = await api.post(`/modules/${moduleId}/audio`, { mimeType: file.type });

  // 2. Upload directly to object storage (no auth header, Content-Type must match)
  await axios.put(data.uploadUrl, file, {
    headers: { 'Content-Type': file.type },
  });

  // 3. Confirm and branch on the resulting status
  const confirmed = await api.post(`/modules/${moduleId}/audio/confirm`, {
    storageKey: data.storageKey,
  });
  if (confirmed.data.sourceAudioUploadStatus !== 'READY') {
    throw new Error('Upload chưa hoàn tất, vui lòng thử lại.');
  }
  return confirmed.data;
}
```

### 3.3 Student uploads a speaking recording

```ts
const { data } = await api.post(`/submission-modules/${submissionModuleId}/audio-upload-url`, {
  mimeType: 'audio/webm',
});
await axios.put(data.uploadUrl, recordingBlob, {
  headers: { 'Content-Type': 'audio/webm' },
});
// then submit the module; the backend probes object storage itself
await api.post(`/submissions/${submissionId}/submit`);
```

## 4. Notes & breaking changes

- **Breaking change:** `POST /api/v1/modules/{moduleId}/audio` is no longer
  `multipart/form-data` with a `file` part. It now takes `application/json` `{ "mimeType" }`
  and returns a presigned URL. Frontend callers using `FormData` must migrate to the 3-step
  flow above.
- **New endpoints:** `POST /api/v1/modules/{moduleId}/audio/confirm` and
  `GET /api/v1/modules/{moduleId}/audio`.
- **Local disk storage was removed.** `LocalAudioStorageAdapter`, `AudioStoragePort` and the
  `app.storage.local-root` property no longer exist. All audio lives in S3-compatible storage.
- **Removed server-side size/signature checks.** Because the backend never receives the bytes, the
  previous 25 MB limit and magic-byte (file signature) validation were dropped. Only the mime-type
  allowlist is enforced. Object storage / CDN policies should enforce size limits if required.
- `sourceAudioDurationSeconds` is not computed and stays `null`.
- The storage key format is unchanged: `modules/{moduleId}/audio/{uuid}.{extension}`.

## 0. Khái niệm chung: presigned direct upload

```text
Client (trình duyệt)                     Backend (Spring Boot)                Kho lưu trữ (S3/R2/MinIO)
      |                                          |                                       |
      |  1. POST .../upload-url  { mimeType }    |                                       |
      |----------------------------------------->|                                       |
      |   { uploadUrl, storageKey, expiresAt }   |                                       |
      |<-----------------------------------------|                                       |
      |                                          |                                       |
      |  2. PUT uploadUrl  (bytes thô, Content-Type = mimeType)                          |
      |--------------------------------------------------------------------------------->|
      |   200 / 204 OK                                                                   |
      |<---------------------------------------------------------------------------------|
      |                                          |                                       |
      |  3. POST .../confirm  { storageKey }     |  kiểm tra objectExists(storageKey)    |
      |----------------------------------------->|-------------------------------------->|
      |   { ...UploadStatus: READY | FAILED }    |                                       |
      |<-----------------------------------------|                                       |
```

Đặc điểm quan trọng:

- Presigned PUT URL **hết hạn** (hiện tại **15 phút**). Hết hạn thì yêu cầu URL mới.
- Header `Content-Type` của lần PUT trực tiếp **phải trùng** với `mimeType` ở bước 1, vì nó đã
  được ký vào URL. Sai `Content-Type` sẽ bị kho lưu trữ từ chối với `403`.
- `storageKey` do backend sinh ra; hãy dùng lại đúng giá trị đó ở các bước sau. Không tự tạo
  `storageKey`.
- Khi `app.storage.s3.enabled=false`, các lệnh gọi storage trả `500` với message
  `"Lưu trữ chưa được cấu hình."`.

## 1. Audio bài nghe của module (giáo viên)

Thay thế endpoint `multipart/form-data` cũ. Upload giờ gồm 3 bước, và backend có thêm endpoint
`GET` để học sinh phát audio.

**Phân quyền:** chỉ giáo viên sở hữu bài tập. `ADMIN` và giáo viên khác nhận `403`.

### 1.1 Yêu cầu URL upload

```http
POST /api/v1/modules/{moduleId}/audio
Authorization: Bearer <access token giáo viên>
Content-Type: application/json

{ "mimeType": "audio/mpeg" }
```

Các giá trị `mimeType` hợp lệ và phần mở rộng của storage key:

| `mimeType`                       | Phần mở rộng |
| :------------------------------- | :----------- |
| `audio/mpeg`, `audio/mp3`        | `.mp3`       |
| `audio/wav`, `audio/x-wav`, `audio/wave` | `.wav` |
| `audio/mp4`, `audio/m4a`, `audio/x-m4a` | `.m4a` |

Phản hồi `200 OK`:

```json
{
  "message": "Lấy link upload audio thành công.",
  "uploadUrl": "https://storage.example.com/bucket/modules/42/audio/<uuid>.mp3?X-Amz-Signature=...",
  "storageKey": "modules/42/audio/<uuid>.mp3",
  "expiresAt": "2026-10-17T12:30:00Z",
  "sourceAudioUploadStatus": "UPLOADING"
}
```

Yêu cầu URL upload lần nữa sẽ **thay thế** audio đang chờ trước đó: object cũ bị xoá (best-effort,
sau khi request commit) và metadata của module trỏ sang key mới với trạng thái `UPLOADING`.

### 1.2 PUT file lên kho lưu trữ

```http
PUT <uploadUrl ở bước 1>
Content-Type: audio/mpeg

<bytes thô của file>
```

Không dùng header `Authorization` ở đây — chữ ký trong URL đã cấp quyền ghi. Upload thành công trả
`200` hoặc `204`. Nếu nhận `403`: URL đã hết hạn hoặc `Content-Type` không khớp `mimeType` ở bước 1.

### 1.3 Xác nhận upload

```http
POST /api/v1/modules/{moduleId}/audio/confirm
Authorization: Bearer <access token giáo viên>
Content-Type: application/json

{ "storageKey": "modules/42/audio/<uuid>.mp3" }
```

Backend kiểm tra object trong kho lưu trữ rồi cập nhật trạng thái module:

Thành công (`200 OK`):

```json
{
  "message": "Xác nhận upload audio thành công.",
  "sourceAudioStorageKey": "modules/42/audio/<uuid>.mp3",
  "sourceAudioUploadStatus": "READY"
}
```

Chưa upload (`200 OK`, trạng thái chuyển `FAILED`):

```json
{
  "message": "File audio chưa được tải lên kho lưu trữ.",
  "sourceAudioStorageKey": "modules/42/audio/<uuid>.mp3",
  "sourceAudioUploadStatus": "FAILED"
}
```

> Trường hợp `FAILED` trả HTTP `200` là có chủ đích: thay đổi trạng thái nằm trong cùng một
> transaction nên trả về trong body để được commit. Client phải rẽ nhánh theo
> `sourceAudioUploadStatus`, **không** theo HTTP status code.

Nếu `storageKey` không thuộc module này, API trả `400` với
`{"error":"storageKey không khớp với module."}`.

### 1.4 Phát / tải audio

```http
GET /api/v1/modules/{moduleId}/audio
Authorization: Bearer <access token giáo viên hoặc học sinh>
```

- Trả về **bytes audio thô** với `Content-Type` là mime type đã lưu và
  `Cache-Control: private, max-age=3600`.
- Phân quyền giống `GET /api/v1/modules/{moduleId}`: giáo viên sở hữu và học sinh là thành viên
  của lớp được phép; còn lại (`ADMIN`, giáo viên khác, học sinh ngoài lớp) nhận `403`.
- `404` với `{"error":"Module chưa có file audio."}` khi module chưa có key audio, hoặc key có
  nhưng object không tồn tại trong kho lưu trữ.

Vì endpoint yêu cầu header `Authorization`, thẻ `<audio src="...">` thuần **không** phát trực tiếp
được. Frontend phải tải bytes rồi tạo object URL:

```ts
const response = await api.get(`/modules/${moduleId}/audio`, { responseType: 'blob' });
const objectUrl = URL.createObjectURL(response.data);
// <audio src={objectUrl} /> — gọi URL.revokeObjectURL(objectUrl) khi unmount
```

### 1.5 Bảng lỗi

| HTTP | Message                                        | Nguyên nhân                                        |
| :--- | :--------------------------------------------- | :------------------------------------------------- |
| 400  | `Module này không hỗ trợ upload audio.`        | Module không phải `LISTENING` (request/confirm).   |
| 400  | `Định dạng file audio không được hỗ trợ.`      | `mimeType` thiếu hoặc không nằm trong allowlist.   |
| 400  | `storageKey không khớp với module.`            | Confirm với key của lần upload khác.               |
| 403  | `Bạn không có quyền thực hiện thao tác này.`   | Không phải giáo viên sở hữu / không phải thành viên.|
| 404  | `Module chưa có file audio.`                   | `GET` trước khi upload, hoặc object bị thiếu.      |
| 500  | `Lưu trữ chưa được cấu hình.`                  | `app.storage.s3.enabled=false`.                    |

## 2. Upload file bài nộp (học sinh)

Luồng bài nộp đã dùng presigned upload từ trước. Tài liệu ở đây để gom cả hai luồng về một chỗ.
Có hai biến thể, thao tác trên **submission module** (không phải assignment module).

**Phân quyền:** học sinh sở hữu bài nộp, và chỉ khi bài nộp đang `IN_PROGRESS`.

### 2.1 File ghi âm bài nói (`audio`)

Hợp lệ khi assignment module là task `RECORDING` **hoặc** có skill `SPEAKING`.

```http
POST /api/v1/submission-modules/{submissionModuleId}/audio-upload-url
Authorization: Bearer <access token học sinh>
Content-Type: application/json

{ "mimeType": "audio/webm" }
```

`mimeType` hợp lệ: `audio/webm` (→ `.webm`), `audio/mpeg` (→ `.mp3`), `audio/wav` (→ `.wav`).

Phản hồi `200 OK`:

```json
{
  "uploadUrl": "https://storage.example.com/...&X-Amz-Signature=...",
  "storageKey": "submissions/<submissionId>/module-<submissionModuleId>/audio.webm",
  "expiresAt": "2026-10-17T12:30:00Z"
}
```

Sau đó PUT bytes lên `uploadUrl` với `Content-Type` trùng khớp. Bài nộp **không có endpoint
confirm**: trạng thái được xác định khi nộp module (xem 2.3).

### 2.2 Tài liệu bài viết (`document`)

Chỉ hợp lệ khi assignment module là `ESSAY` (task `REWRITE` bị từ chối có chủ đích — rewrite trả
lời câu hỏi như quiz).

```http
POST /api/v1/submission-modules/{submissionModuleId}/document-upload-url
Authorization: Bearer <access token học sinh>
Content-Type: application/json

{ "mimeType": "application/pdf" }
```

`mimeType` hợp lệ:
`application/pdf` (→ `.pdf`),
`application/vnd.openxmlformats-officedocument.wordprocessingml.document` (→ `.docx`).

Cấu trúc phản hồi giống 2.1, với `storageKey`
`submissions/<submissionId>/module-<submissionModuleId>/essay.<ext>`.

Lỗi của cả hai dùng `400` với `"Không thể upload ghi âm cho phần làm bài này."` /
`"Không thể upload tài liệu cho phần làm bài này."` (sai loại module hoặc bài nộp không
`IN_PROGRESS`) và `"Định dạng file không được hỗ trợ."` (mime type sai).

### 2.3 Nộp module

```http
POST /api/v1/submissions/{submissionId}/submit
```

Với module dạng file, backend tự kiểm tra object trong kho lưu trữ theo các key mong đợi:

- Ứng viên audio, theo thứ tự: `audio.webm`, `audio.mp3`, `audio.wav`.
- Ứng viên tài liệu, theo thứ tự: `essay.pdf`, `essay.docx`.

Key đầu tiên tồn tại được lưu với `audioUploadStatus`/`docUploadStatus` = `READY`; nếu không có key
nào thì trạng thái giữ `UPLOADING`. **Module vẫn được nộp trong cả hai trường hợp** — thiếu file
không làm lệnh nộp thất bại, chỉ ghi nhận là chưa upload.

## 3. Ví dụ đầy đủ

### 3.1 Giáo viên upload audio bài nghe (curl)

```bash
TOKEN="<access token giáo viên>"
MODULE_ID=42

# 1. Yêu cầu presigned URL
RESPONSE=$(curl -s -X POST "http://localhost:8080/api/v1/modules/$MODULE_ID/audio" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"mimeType":"audio/mpeg"}')

UPLOAD_URL=$(echo "$RESPONSE" | jq -r '.uploadUrl')
STORAGE_KEY=$(echo "$RESPONSE" | jq -r '.storageKey')

# 2. Upload bytes trực tiếp lên kho lưu trữ
curl -s -X PUT "$UPLOAD_URL" \
  -H "Content-Type: audio/mpeg" \
  --data-binary @lesson.mp3

# 3. Xác nhận
curl -s -X POST "http://localhost:8080/api/v1/modules/$MODULE_ID/audio/confirm" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"storageKey\":\"$STORAGE_KEY\"}"

# 4. Phát lại
curl -s "http://localhost:8080/api/v1/modules/$MODULE_ID/audio" \
  -H "Authorization: Bearer $TOKEN" --output downloaded.mp3
```

### 3.2 Giáo viên upload audio bài nghe (trình duyệt / axios)

```ts
async function uploadModuleAudio(moduleId: number, file: File) {
  // 1. Xin presigned URL từ backend
  const { data } = await api.post(`/modules/${moduleId}/audio`, { mimeType: file.type });

  // 2. Upload trực tiếp lên kho lưu trữ (không cần auth, Content-Type phải trùng)
  await axios.put(data.uploadUrl, file, {
    headers: { 'Content-Type': file.type },
  });

  // 3. Xác nhận và rẽ nhánh theo trạng thái trả về
  const confirmed = await api.post(`/modules/${moduleId}/audio/confirm`, {
    storageKey: data.storageKey,
  });
  if (confirmed.data.sourceAudioUploadStatus !== 'READY') {
    throw new Error('Upload chưa hoàn tất, vui lòng thử lại.');
  }
  return confirmed.data;
}
```

### 3.3 Học sinh upload file ghi âm bài nói

```ts
const { data } = await api.post(`/submission-modules/${submissionModuleId}/audio-upload-url`, {
  mimeType: 'audio/webm',
});
await axios.put(data.uploadUrl, recordingBlob, {
  headers: { 'Content-Type': 'audio/webm' },
});
// sau đó nộp module; backend tự kiểm tra object trong kho lưu trữ
await api.post(`/submissions/${submissionId}/submit`);
```

## 4. Lưu ý & thay đổi phá vỡ tương thích

- **Thay đổi phá vỡ tương thích:** `POST /api/v1/modules/{moduleId}/audio` không còn là
  `multipart/form-data` với part `file`. Nay nhận `application/json` `{ "mimeType" }` và trả về
  presigned URL. Frontend đang dùng `FormData` phải chuyển sang luồng 3 bước ở trên.
- **Endpoint mới:** `POST /api/v1/modules/{moduleId}/audio/confirm` và
  `GET /api/v1/modules/{moduleId}/audio`.
- **Đã xoá lưu trữ trên disk local.** `LocalAudioStorageAdapter`, `AudioStoragePort` và property
  `app.storage.local-root` không còn tồn tại. Toàn bộ audio nằm trong kho lưu trữ tương thích S3.
- **Đã bỏ kiểm tra kích thước/chữ ký phía server.** Vì backend không nhận bytes, giới hạn 25 MB và
  kiểm tra magic-byte (chữ ký file) trước đây đã bị bỏ. Chỉ còn allowlist mime type. Nếu cần giới
  hạn dung lượng, hãy cấu hình ở kho lưu trữ / CDN.
- `sourceAudioDurationSeconds` không được tính và luôn là `null`.
- Định dạng storage key không đổi: `modules/{moduleId}/audio/{uuid}.{extension}`.
